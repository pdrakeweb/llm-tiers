| D-005 | Tiers: on-device (Gemini Nano, then downloadable models), LAN (any OpenAI-compatible server, e.g. LiteLLM or llama.cpp), cloud (OpenRouter or any OpenAI-compatible URL); reachability-checked fallback. | Pete (words), via NextRep D-015/D-016: "make sure this would work if I'm running litellm and llama.cpp somewhere on my local network where if reachable it can use that and if not it can fall back to something else" |
| D-006 | Privacy is a routing rule: identifiers never leave the device; personal data only with per-request approval. | Pete (words), via NextRep D-017 |
| D-007 | Repository and library name `llm-tiers`; repository public from the start; Maven namespace decided before 0.1.0. | Pete (picked) "drivesync + llm-tiers", "Public from the start" |

| D-009 | `Result.Answer` gains `incomplete: ProviderFailure? = null`. Non-null means the provider failed after its first token: the text is partial and this is why (ARCHITECTURE §4 first-token commit). | Pete (picked) "Add Answer.incomplete", 11 Nov 2026 |
| D-010 | A pinned provider is never replaced, whatever the failure: the request ends `NoneAvailable` with the reason. This is the strict reading of A-3; ARCHITECTURE §4 could be read as allowing a reported fallback for failures other than `AuthRejected`/`KeyMissing`. A pin also overrides the request's mode, and a pinned provider is tried even while cooling down. | Proposed (T1 implementation) |
| D-011 | `safeToRetry` defaults to false. Failures that prove the request was not processed (`Unreachable`, `AuthRejected`, `KeyMissing`, `RateLimited`, `ContextTooLong`, `ModelNotReady`, `Busy`, `LocalNetworkPermissionDenied`, a failed probe) and `Escalate` always fall back. Ambiguous ones (`Timeout`, `FirstTokenTimeout`, `Stalled`, `Server`, `Other`) fall back only when the request is marked `safeToRetry` or has an idempotency key. Consequence: an unmarked request does not move on after a first-token timeout. | Proposed (T1 implementation) |
| D-012 | A hard deadline bounds the whole request, fallbacks included. When it passes the result is `NoVerdict` and any partial text is dropped. | Proposed (T1 implementation) |
| D-013 | `Blocked` means no provider was tried and privacy (a sensitivity the provider does not accept, or a refused approval) excluded at least one. A short-circuit hook that throws or exceeds 5 s also yields `Blocked`: it fails closed and no model is called. An approval callback that throws or exceeds 2 min counts as a refusal. | Proposed (T1 implementation) |
| D-014 | Health defaults: 3 failures in 60 s take a provider out for 30 s; `Unreachable`, `ModelNotReady`, `LocalNetworkPermissionDenied`, `AuthRejected` and `KeyMissing` take it out at once; `Busy` and `RateLimited` for 10 s. A provider that fails while probing goes out for twice as long, up to 10 min. Health is keyed by provider and network, so a network change starts fresh. LAN and on-device providers are probed (1 s) before use and the result is trusted for 60 s; cloud providers are never probed. | Proposed (T1 implementation) |
| D-015 | Only the latency budget is implemented. A cost budget needs cost data that `Capabilities` does not carry; deferred until a consumer needs it. | Proposed (T1 implementation) |
| D-016 | `Identifier` items are removed for every provider, on-device included ("stripped", DESIGN §3). | Proposed (T1 implementation) |
| D-017 | `:openai` is in-house over OkHttp and kotlinx.serialization (ARCHITECTURE §1). The app names the model and declares its capabilities; `/v1/models` does not report them reliably. | Proposed (T1 implementation) |
| D-018 | `:openai` never follows HTTP redirects and disables OkHttp's silent connection retry: a redirect would re-send the prompt to a host nobody approved, and a silent retry would send a not-safe-to-retry request twice. An `error` object inside a 200 stream is ambiguous for retry safety (never `RateLimited`/`AuthRejected`), because the server had accepted the request. | Proposed (T1 review fix) |
| D-019 | App callbacks (`approve`, short-circuit, `capabilities()`, `probe()`) and provider streams run in jobs that are cancelled but not joined, so one that ignores cancellation cannot hang a request. A learned timeout that fires is forgotten and relearned from the defaults. | Proposed (T1 review fix) |
| D-020 | Android pins (verified 11 Nov 2026): AGP 9.5.1, Gradle 9.9.1, compileSdk 37, library minSdk 26, sample targetSdk 37 so the Android 17 local-network rule is exercised. | Proposed (T2 implementation) |
| D-021 | The cleartext rule is enforced by an OkHttp network interceptor on the connected address (`privateCleartextOnly()`), because a network security config cannot express address ranges. A blocked request surfaces as `Unreachable`. | Proposed (T2 implementation) |
| D-022 | `GeminiNano()` takes no `Context` (the ML Kit client needs none). The conversation is flattened to one prompt; capabilities are text and vision, no JSON schema, context from the model's own token limit. `BUSY`, background-use and battery-quota errors map to `Busy`. | Proposed (T2 implementation) |
| D-023 | The sample app uses plain platform views, no Compose or DI, to keep the library's sample free of extra dependencies. The encrypted key store listed for `:android` in ARCHITECTURE §1 is not in the T2 roadmap row and is not built; the sample keeps the key in memory only. | Proposed (T2 implementation) |
| D-024 | The LiteRT-LM provider is its own optional module, `:litert` (`llm-tiers-litert`, package `io.github.pdrakeweb.llmtiers.litert`), not part of `:android` as ARCHITECTURE §1 first said. Measured in LiteRT-LM 0.19.1: one native library per ABI, 22.7 MB for arm64-v8a and 26.9 MB for x86_64 (about 10 MB each compressed), against 0.2 MB of Java classes. It is a single prebuilt library, so the library cannot shrink it; an app limits the cost by shipping an App Bundle or filtering ABIs. `:android` no longer carries any native code. `:litert` depends only on `:core` and takes the model file as a function, so it does not depend on `:model-manager`. | Pete (words): "If we can't possibly shrink that then it should be a separate optional module/library", 12 Nov 2026 |
| D-025 | `:model-manager` trusts only files it verified: size and SHA-256 are checked when a download finishes, the size again on every `state()` call. A checksum or size mismatch deletes the file and is not called recoverable; a failed download or lack of space is. Models are stored in the app's external files directory because `DownloadManager` cannot write to internal storage. | Proposed (T3 implementation) |
| D-026 | LiteRT-LM runs on the CPU backend, one request at a time (`Busy` otherwise). A model load is never cancelled: if the caller's first-token timeout fires, the load finishes in the background. A file that fails to load is `ModelNotReady`. | Proposed (T3 implementation) |
| D-027 | The library lets the user choose the on-device model. `:model-manager` ships a starter catalog (`OpenModels`: Qwen3 0.6B, Gemma 4 E2B, Gemma 4 E4B, all Apache 2.0, pinned by revision and SHA-256), apps can add their own specs, several models can be on the device at once, and `fit()` advises on memory and storage without blocking. | Pete (words): "the system should let the user pick and actually use the larger models in their app", 11 Nov 2026 |
| D-028 | `fit()` reports `LowMemory` when the device has less memory than twice the model's file size. The memory guidance in the catalog's documentation (8 GB for E2B, 12 GB for E4B) is a rough rule, not a measurement. | Proposed (T3 implementation) |
| D-029 | A model file keeps the extension of its URL. LiteRT-LM identifies the format by extension and rejects a correctly downloaded `.litertlm` saved under another name (found when the first real model failed to load). | Proposed (T3 implementation) |
| D-030 | Contract-test settings may live in a git-ignored `.env` in the repository root, loaded by Gradle for the test process only; the real environment wins. `.env.example` is committed. | Pete (words): "Do we use a .env file that is excluded from git in the local checkout to store the LLM tiers stuff for testing?", 11 Nov 2026 |
| D-031 | Reasoning counts as alive, not silent. `ProviderEvent.Thinking` (no content) and `Event.Thinking(provider)` are added to the types in ARCHITECTURE §2. `:openai` emits it for `reasoning_content` / `reasoning` deltas and never passes the reasoning text on. Found when the LAN contract test met a model that streamed only reasoning for 28 s to over 2 minutes before its first word. | Pete (picked) "Yes, add it", 11 Nov 2026 |
| D-032 | Thinking timing: the first sign of life must come within the first-token timeout; then life must continue within the stall timeout; the first token must come within `TimeoutConfig.thinking` (default 2 minutes) or the attempt ends as `FirstTokenTimeout`. The app is told once per attempt. | Proposed (follows D-031) |
| D-033 | Two tiers, `ON_DEVICE` and `REMOTE`, each with any number of providers. A home server, a self-hosted gateway and a cloud API are all remote; whether to probe one before use is a per-provider setting (`probeBeforeUse`, on by default for plain-HTTP URLs). Supersedes the three tiers of D-005 and the LAN wording in DESIGN.md and ARCHITECTURE.md. | Pete (words): "Is openrouter fundamentally different from using one's own openapi account or local LAN LLM with litellm or whatever? If not, then we should just offer ondevice (multiple?) and remote (multiple)", 11 Nov 2026 |
| D-034 | Developers choose how providers are ordered and run: `rank` (`AppOrder`, `Quality`, `Speed`, `Weighted`) in the pure policy, and `strategy` (`Sequential`, `Race`, `Hedged`, `FastThenBest`, `BestOf`) in the executor. ADR-0002; `docs/STRATEGIES.md`. | Pete (words): "There are probably others (first to answer, based on weighted quality of answers, latency, fast-then-quality, etc). FIgure out the main possible/probably algorithms and implement them", 11 Nov 2026 |
| D-035 | Offline needs no setting: with no network every remote provider is skipped as `Offline` and on-device providers are tried. A user's explicit choice is `OnlyOnDevice`, `OnlyRemote` or a pin. | Pete (words): "there is the pre-existing one … where it uses local when in airplane mode. Or the user can explicitly select", 11 Nov 2026 |
| D-036 | Details of the strategies that the request left open: a concurrent strategy applies only to a request marked safe to retry; `FastThenBest` asks approval before the draft and replaces the draft only when the remote answer is complete; `BestOf` streams nothing until it has chosen; a provider with no latency history is ranked as 1 s on device and 2 s remote; quality is a number the app declares per provider. | Proposed (follows D-034) |
| D-037 | `:openai` gains OpenRouter helpers in package `io.github.pdrakeweb.llmtiers.openai.openrouter`: `OpenRouter.provider(…)` (an `OpenAiCompatible` with OpenRouter's attribution headers `HTTP-Referer`, `X-OpenRouter-Title` and its older alias `X-Title`, optional `X-OpenRouter-App-Visibility: hidden`, and every existing parameter passed through); `OpenRouterCatalog` (the live `GET /models` list, public, no key sent); `OpenRouter.checkKey` (`GET /key`). Apps pick OpenRouter models from the live list, never from a list compiled into the app: ids are retired and renamed (a `:free` variant disappears; `claude-sonnet-4-6` is spelled `claude-sonnet-4.6`), and a stale id fails every request. Refines D-017 for OpenRouter only: its list does report capabilities, so a catalog entry may supply them; other servers are still declared by the app. | Proposed (requested for a consumer integration whose hard-coded OpenRouter list had gone stale) |
| D-038 | How the OpenRouter helpers behave. Every failure is a value (`CatalogResult.Unreachable` / `HttpError(code)` / `Malformed`; `KeyStatus.Missing` / `Rejected` / `Unreachable` / `HttpError` / `Malformed`); nothing throws for network, HTTP or parsing problems, and cancelling the caller cancels the call. Redirects are not followed (as D-018) and a body over 16 MiB is `Malformed`. A successful catalog fetch is reused for `cacheFor` (default 1 hour); failures are never cached, and `lastGood` keeps the last list for offline use. Mapping: `jsonSchema` only from `structured_outputs` (a model that lists only `response_format` may offer JSON mode but not a schema, and `Needs.structuredJson` sends a strict schema); `vision` from an `image` input modality; `maxContext` from `context_length`, else `top_provider.context_length`, else the library default; prices are exact `BigDecimal` US dollars per token, and the `-1` OpenRouter's routers report becomes null ("no fixed price"); `isFree` is a `:free` id or both prices zero. Entries without an id are skipped, unknown fields ignored. Header values are reduced to printable ASCII (accents dropped), because OkHttp rejects anything else at request time. A key with characters no header can carry is `Rejected` without being sent. | Proposed (follows D-037) |
| D-039 | `:android` gains `SecretStore`, the encrypted key store ARCHITECTURE §1 listed and D-023 left unbuilt. AES-256-GCM under one non-exportable Android Keystore key (alias `llm_tiers_secret_store`; no StrongBox, which is slow and missing on many phones; no user-authentication requirement, so background requests can read a key); ciphertext `v1:<IV>:<ciphertext>` in the private SharedPreferences file `SecretStore.PREFS_FILE_NAME` (`llm_tiers_secrets`); the entry name is bound in as associated data, so a ciphertext moved to another name does not decrypt. Reads never throw: a value that can never decrypt (no key, as after a restore or device transfer, which never carry Keystore keys; an invalidated key; altered or foreign text) reads as null and its entry is deleted, and an invalidated key is discarded so the next `put` makes a new one; a failure that may be temporary reads as null and keeps the entry. `put` returns whether the value reached the disk. A library cannot set an app's backup rules, so the constant is documented for apps to exclude. The example app's hand-written `KeyVault` is replaced by it. No helper is added for "a build-time key as fallback": the guide keeps "never put a key in source or `BuildConfig`" for distributed apps and shows the one-line pattern, with that warning, for builds that are never distributed. | Proposed (requested for a consumer integration) |
